## 2. ПОСТАНОВКА ЗАДАЧІ ТА РОЗПОДІЛ РОЛЕЙ

### 2.1. Загальний опис системи
Проєкт моделює роботу автоматизованої конвеєрної лінії контролю якості на промисловому підприємстві із взаємодією трьох паралельних процесів:
1. **Батьківський процес (Керівник зміни / Supervisor, Issue #1):**
   - Ініціалізація загальносистемних ресурсів IPC.
   - Створення дочірніх процесів (`fork()`).
   - Моніторинг метрик якості готових виробів через чергу повідомлень (`POSIX Message Queue / System V MQ`).
   - Коректне завершення зміни та очищення ресурсів.
2. **Дочірній процес 1 (Робітник 1 — Перевіряючий / Quality Inspector, Issue #2):**
   - Отримання сирих деталей з конвеєра, виконання первинного огляду на наявність дефектів.
   - Передача проміжних результатів через іменований канал (`FIFO / named pipe`).
   - Періодичний вихід на перерву згідно з графіком відпочинку.
3. **Дочірній процес 2 (Робітник 2 — Тестувальник / Quality Tester, Issue #3):**
   - Зчитування проміжних виробів із каналу FIFO.
   - Виконання інструментального тестування якості та формування числової оцінки (0–100).
   - Відправка фінальних метрик керівникові через чергу повідомлень.
   - Періодичний вихід на перерву за семафорним регламентом.

### 2.2. Завдання модуля Issue #4 (моя частина)
1. **Спільна інфраструктура (`include/common.h`):**
   - Визначення шляхів та імен для IPC-ресурсів (FIFO, черга повідомлень, семафор).
   - Стандартизація структур даних (`IntermediateItem`, `FinalMetric`, `struct msg_buffer`).
   - Константи статусів, кодів браку та помилок.
2. **Модуль синхронізації відпочинку (`include/semaphore_utils.h`, `src/semaphore_utils.c`):**
   - Забезпечення правила взаємного виключення: **у кімнаті відпочинку одночасно може перебувати не більше одного робітника**.
   - Атомарна фіксація виходу та повернення з перерви у файл `break_log.txt`.
3. **Модульне складання (`Makefile`):**
   - Складання за стандартом C11 з жорсткими прапорцями компілятора (`-Wall -Wextra -pedantic`).
   - Цілі `all`, `parent`, `worker1`, `worker2`, `test_semaphores`, `clean`.
   - Автоматичне очищення залишкових IPC-ресурсів (через `ipcrm` та `/dev/shm`).
4. **Тестовий стенд (`tests/test_semaphores.c`) та заглушки робітників:**
   - Верифікація роботи двох паралельних процесів без взаємних блокувань (дедлоків) та умов гонок (race conditions).

## 3. ТЕОРЕТИЧНИЙ АНАЛІЗ ТА ОБҐРУНТУВАННЯ ТЕХНІЧНИХ РІШЕНЬ

### 3.1. Порівняння та вибір IPC-семафорів: POSIX проти System V

| Критерій | System V Semaphores (`semget`, `semop`, `semctl`) | POSIX Named Semaphores (`sem_open`, `sem_wait`, `sem_post`) |
| :--- | :--- | :--- |
| **Стандартність** | Застарілий API UNIX System V (1983 р.) | Сучасний стандарт IEEE POSIX 1003.1b (Realtime Extensions) |
| **Простір імен** | Числові ключі `key_t`, генерація через `ftok()` (ризик колізій і конфліктів шляхів) | Рядкові імена у форматі `/name`, що відображаються у віртуальну пам'ять `/dev/shm` |
| **Складність API** | Висока: вимагає масивів `struct sembuf`, маніпуляцій з прапорцями `SEM_UNDO`, використання union `semun` | Низька: лаконічні виклики `sem_wait()` / `sem_post()`, аналогічні м'ютексам |
| **Керування ресурсами** | Залишаються в пам'яті ядра навіть після збою програми, вимагають ручного виклику `ipcrm` | Автоматичне видалення дескрипторів ядром; просте видалення через `sem_unlink()` |
| **Сумісність з потоками/процесами** | Тільки процеси | Процеси та потоки (уніфікований інтерфейс) |

**Висновок:** Для реалізації контролю перерв обрано **іменовані POSIX-семафори** (`SEM_NAME = "/zavod_break_sem"`), оскільки вони надають гарантовану безпеку простору імен, надійність при паралельному доступі споріднених і неспоріднених процесів, а також простий і зрозумілий API.

### 3.2. Запобігання гонкам даних під час логування (Atomic Logging via O_APPEND)
Для запису подій у файл журналу `break_log.txt` замість стандартного буферизованого потоку `fopen()`/`fprintf()` використано системний виклик `open()` із прапорцями:
```c
int fd = open(LOG_FILE, O_WRONLY | O_CREAT | O_APPEND, 0644);
```
Відповідно до стандарту POSIX:
- Прапорець `O_APPEND` гарантує, що операційна система ядром переміщує покажчик позиції в кінець файлу **атомарно безпосередньо перед кожним викликом `write()`**.
- Навіть при одночасному зверненні кількох незалежних процесів записи не перекривають один одного і не спотворюють структуру файлу.
- Форматування часу виконується засобами системної бібліотеки через виклики `time()`, `localtime()` та `strftime()`.

### 4.2. Опис ключових функцій модуля `semaphore_utils.c`
1. `init_break_semaphore(void)`:
   - Створює або підключається до наявного семафора за допомогою `sem_open(SEM_NAME, O_CREAT, 0644, 1)`.
   - Зберігає PID процесу-творця для забезпечення коректного фінального очищення.
2. `leave_for_break(int worker_id)`:
   - Здійснює блокуюче очікування `sem_wait()`, коректно обробляючи випадки переривання системного виклику сигналами (`EINTR`).
   - Фіксує системний час початку перерви для даного `worker_id`.
3. `return_from_break(int worker_id)`:
   - Фіксує поточний час повернення робітника.
   - Форматує рядок за шаблоном: `[Робітник %d] Вихід: %s — Повернення: %s\n`.
   - Атомарно записує подію в `break_log.txt` через виклик `write()`.
   - Звільняє семафор за допомогою `sem_post()`, відкриваючи доступ іншим робітникам.
4. `cleanup_break_semaphore(void)`:
   - Закриває дескриптор `sem_close()`.
   - Якщо виклик здійснюється батьківським процесом-творцем, викликає `sem_unlink()`, видаляючи семафор із пам'яті системи.

### 5.2. Аналіз результатів
1. **Взаємне виключення:** Робітник #2, намагаючись зайти на перерву, був коректно заблокований семафором, доки Робітник #1 не повернувся та не звільнив ресурс.
2. **Атомарний лог:** У журналі `break_log.txt` зафіксовано обидва інтервали без накладання рядків чи втрати інформації.
3. **Чистота ресурсів:** Після завершення роботи у системі не залишилось висячих дескрипторів семафорів (`/dev/shm` чистий, `ipcs -s` показує відсутність блоків).
